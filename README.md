# Антифрод по метаданным вызовов (CDR)

Находит схемы мошенничества S1–S7 в записях коммутатора, не трогая легальные массовые источники D1–D5,
и объясняет каждое решение: оценка 0–100 с вкладом факторов, рекомендация, решение по автоблокировке.

## Быстрый запуск (Windows)

Нужен Python 3.11 или новее. Лучше **3.13**: под него есть CatBoost. На 3.15 CatBoost ещё не собран —
всё работает, но модель «второго мнения» заменяется логистической регрессией (ответ тот же, подсказки аналитику хуже).
Если установлены обе версии, `start.bat` сам выберет 3.13.

1. Архив `cdr_out.zip` ищется в папке проекта, уровнем выше и в «Загрузках» — переносить не нужно.
2. Дважды щёлкните `start.bat` — он создаст окружение, установит библиотеки, посчитает всё и откроет консоль в браузере.

Или вручную в терминале VS Code:

```
python -m pip install -r requirements.txt
python run_all.py "C:\путь\к\cdr_out.zip"
```

`run_all.py` выполняет прогон (3–5 мин: правила ~1,5 мин, две модели CatBoost ~2–3 мин), проверку на синтетике (~30 с)
и открывает http://127.0.0.1:8000.

## Команды

| Команда | Что делает |
|---|---|
| `python -m antifraud run [источник]` | полный прогон: очистка → признаки → детекторы → оценка → CatBoost ×2 → время до обнаружения и ущерб → база |
| `python -m antifraud evaluate` | синтетика с известной разметкой и сдвигом параметров: точность/полнота |
| `python -m antifraud serve` | веб-консоль и API на http://127.0.0.1:8000 (документация API: /docs). Если порт занят — берётся следующий; после нового прогона сервер подхватывает результаты сам |
| `python -m antifraud synth папка` | сгенерировать синтетические CDR + `truth.json` |
| `python -m pytest` | тесты |

Источник — `cdr_out.zip` или папка с `*.cdr`.

## Как устроено

```
CDR (zip/папка) → очистка → признаки номеров → правила S1–S7 + легальные профили D1–D5 → оценка 0–100 и политика
                                            ↘ CatBoost на размеченной синтетике (независимая проверка, без ответов правил)
                                            ↘ CatBoost на ответах правил (пограничные номера для аналитика)
              → потоковый прогон: время до обнаружения и ущерб в рублях → база (PostgreSQL/SQLite) → API и консоль
```

**Две модели CatBoost.**
- *На размеченной синтетике* — обучена на синтетике с известной разметкой (7 схем, 5 типов ловушек, обычные абоненты,
  разброс параметров) плюс случайные реальные номера как фон. Ответов правил не видит, поэтому её совпадение с правилами
  на реальных CDR — независимая проверка. Для сравнения считается и вариант «только синтетика»: он почти безошибочен на
  синтетике, но на реальных данных отмечает тысячи обычных номеров — это главный довод не полагаться на одну синтетику.
- *На ответах правил* — второе мнение и поиск пограничных номеров.

Обе модели считаются в момент запроса: карточка номера и проверка вызова показывают вероятность, класс схемы и вклады SHAP.

**Экономический эффект.** Объёмы вреда (минуты перезвонов на платные номера, трафик SIM-box, жертвы вишинга…) считаются
по CDR, доля «после обнаружения» — по потоковому прогону, деньги — по тарифам из `[economics]` в `config.toml`
(допущения и публичные ориентиры с источниками; замените на тарифы оператора).

## База данных

Результаты прогона, номера с решениями, группы и **журнал решений** по каждому вызову, проверенному через API, пишутся в базу.

- По умолчанию — файл SQLite `out/antifraud.db`, ничего ставить не нужно.
- PostgreSQL — укажите строку подключения в `config.toml`, раздел `[database]`, или в переменной `DATABASE_URL`:
  `postgresql+psycopg://postgres:ПАРОЛЬ@localhost:5432/antifraud` (база создаётся автоматически).
- `docker compose up --build` поднимает PostgreSQL и сервис вместе (данные — в `data/cdr_out.zip`).

Признаки всех номеров (375 тыс. строк) хранятся в Parquet — это хранилище признаков для моделей.

## Результаты (папка `out/`)

- `answer.txt` — файл ответа (`номер;схема`), `answer_strict.txt` — без платных номеров C и подменённых номеров
- `evidence.csv` — объяснение по каждому номеру
- `quarantine.csv` — отброшенные строки с причиной; `summary.json` — сводка
- `eval.json`, `realtime.json`, `ml_metrics.json`, `ml_synth.json` — качество, время до обнаружения и ущерб, метрики обеих моделей
- `model.cbm`, `model_synth_0.cbm`, `model_synth_1.cbm` — модели для оценки в момент запроса
- `antifraud.db` — база SQLite (если не задан PostgreSQL)

## Структура

```
config.toml            все пороги детекторов, скоринга и политики
antifraud/ingest.py    чтение zip/папки, исправление и карантин битых строк, дубли
antifraud/features.py  поведенческие признаки номера
antifraud/detectors.py детекторы S1–S7, легальные D1–D5, сборка групп
antifraud/scoring.py   оценка 0–100 из факторов, рекомендации, автоблокировка, белый список
antifraud/ml.py        CatBoost + SHAP на ответах правил: второе мнение и номера на ручную проверку
antifraud/ml_synth.py  CatBoost на размеченной синтетике: независимая проверка ответа на реальных CDR
antifraud/economics.py ущерб по схемам в минутах, жертвах и рублях; сколько останавливает онлайн-обнаружение
antifraud/db.py        база: прогоны, номера, группы, журнал решений (PostgreSQL или SQLite)
antifraud/realtime.py  потоковый прогон: время до обнаружения, предотвращённый вред
antifraud/synth.py     генератор синтетики; evaluate.py — сценарии устойчивости
app/                   FastAPI + страница консоли аналитика
tests/                 pytest
docker-compose.yml     PostgreSQL + сервис
```

## Docker

```
docker build -t antifraud .
docker run --rm -p 8000:8000 -v "%cd%\data:/data" antifraud     # в data лежит cdr_out.zip
```
